## Slice 014-04 — live-session "running now" enrichment (optional)

**Goal:** Add an **optional** "running now" indicator to the card, sourced from
live-session data, enriching the derived "in flight" signal with what is actually
active right now — and degrading cleanly to today's branch/worktree/draft-PR
derivation when the live-session source is absent. This is the seam to the
engineer daily-driver; the manager view must never hard-depend on it.

**DoR:**
- ✅ Assumption **A4** verified as the first task: a local, read-only source
  reports which configured Gauge projects have an active Claude Code session now
  (session registry / lock / open-transcript heuristic). The confirmed source
  and its shape are recorded here before the enrichment is built. If no such
  source exists, the slice degrades to **absent-only** (AC3 still holds; ACs
  1–2 are recorded as blocked-on-source rather than fabricated).
- ✅ Slice 014-01 landed (the thin client exists as the home for the
  session-signal seam).

**Acceptance Criteria:**

1. **"Running now" when present.** When the live-session source reports an active
   session for a project, the card shows a "running now" indicator. Observable:
   a fixture with an active session renders the indicator; one without does not.
2. **Enriches, never overrides, "in flight".** The live signal augments the
   existing in-flight derivation (branches/worktrees/draft PRs) — it adds the
   "active now" fact without discarding or contradicting the derived in-flight
   set. The derived signal remains the base; the live signal is additive.
3. **Absent-safe by construction.** With the live-session source missing,
   unreadable, or empty, the card renders exactly today's behavior (no "running
   now", in-flight from derivation) with no error and no `unknown` regression.
   A test runs the full read layer with the source absent and asserts byte-for-
   byte parity with the pre-slice card for the in-flight region.
4. **Read-only and private.** The live-session read touches no source repo and
   surfaces no session content beyond an active/inactive fact per project (no
   transcript text, no PII) — consistent with the private-data constraint.

**Edge cases to cover explicitly:** source present but reports zero active
sessions (indicator absent, no error); a session active in a project not in the
Gauge config (ignored); a stale/lingering session lock (documented staleness
window or explicit "unknown", never a false "running now"); source read throws
(caught, degrades to absent).
